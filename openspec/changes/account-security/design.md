# 账户安全设计

## 边界与接口

沿用单管理员、PostgreSQL 持久会话、同源 Cookie 与现有 CSRF 校验。后端负责所有验证、锁定、过期、消费和权限决定，前端状态不能替代授权。普通状态只返回 `totpEnabled`、`recoveryCodesRemaining` 和 `otherSessionsCount`，不返回因子密钥、验证码、恢复码、密码哈希或会话令牌。

敏感操作统一重新验证 `currentPassword`；已启用 TOTP 时还需 `code`，接受六位动态码或格式化的高熵恢复码。原密码或因子错误使用可修正的业务错误；真正无会话、会话失效及无效登录挑战继续使用未认证错误，避免错误密码把当前有效会话误判为过期。

## TOTP 与兼容

- 使用维护中的 OTP 库，固定 SHA-1、六位数字、30 秒时间步及最多前后一个时间步的容差；不自行实现密码算法。
- 为每次绑定生成独立的随机 Base32 种子；`otpauth://totp/` 配置使用 Tattoo issuer、管理员标识、标准算法与周期参数，二维码由本地库生成，不访问第三方二维码接口。
- 种子复用现有主密钥加密机制持久化；只有通过密码重新验证后的绑定响应可返回待绑定种子与 URI。普通状态、日志与失败响应不暴露种子。
- 持久化最后成功使用的时间步，在事务锁内验证并更新；已消费或更早的时间步不得再次用于登录或敏感操作。绑定成功本身消费该时间步，界面需说明已用验证码应等待更新。
- 验证器和 NAS 需要正确的系统时间；本项不接入 Google/Microsoft 账户登录或推送批准服务。

## 两阶段登录与限错

密码正确且未启用 TOTP 时保留原有登录方式。启用后，第一阶段仅发短期 HttpOnly 挑战 Cookie，数据库只保存随机挑战值的哈希及其账户、凭据版本、到期和尝试状态；此时不建立完整会话。第二阶段验证 `code`，成功后原子消费挑战和因子，才创建完整会话并撤销挑战 Cookie。

挑战最长有效 5 分钟、最多 5 次失败、成功只能使用一次；在应用重启后也遵守数据库中的过期与尝试状态。返回密码登录时清理挑战。账户级因子错误统计同样持久化：5 分钟内 10 次失败锁定 5 分钟，锁定期间请求不延长锁定。重新获取挑战、切换 IP 或重启不能绕过账户级限制；原有密码/IP 限流继续保留。

失败计数和挑战作废不能被随后抛出的事务异常回滚。错误结果在事务提交后转换为 HTTP 失败。并发验证同一 TOTP 时间步或恢复码只能有一次成功。

## 绑定、恢复码和安全变更

密码重新验证后创建有 `setupId`、10 分钟到期时间和当前会话约束的待绑定记录。确认、取消必须同时匹配 `setupId` 与当前会话；确认正确动态码后才把密钥转为已启用。替换、取消、到期、退出或当前会话失效的待绑定材料不能再启用。

启用或重新生成时产生 10 个独立的 128 bit 恢复码。仅哈希入库；明文只在成功响应展示一次，前端仅保留在组件内存中，提供复制/下载和“已安全保存”的明确确认。未保存恢复码或尚在绑定流程时受页面导航和关闭提醒保护。正常状态只显示剩余数量，不能再次读取明文。重新生成立即废弃整个旧集合，消费恢复码在事务内完成；不把恢复码写入 URL、本地存储或日志。

| 操作           | 重新验证                         | 当前会话               | 其他会话、挑战与待绑定          |
| -------------- | -------------------------------- | ---------------------- | ------------------------------- |
| 修改密码       | 原密码；已启用时加因子           | 轮换 Cookie 并保持登录 | 撤销/清理                       |
| 启用 TOTP      | 绑定前原密码，确认时待绑定动态码 | 轮换并保持登录         | 撤销/清理                       |
| 关闭 TOTP      | 原密码及已绑定因子               | 轮换并保持登录         | 撤销/清理，废弃全部恢复码       |
| 重新生成恢复码 | 原密码及已绑定因子               | 轮换并保持登录         | 撤销/清理，废弃旧码             |
| 退出其他会话   | 原密码；已启用时加因子           | 保留当前令牌           | 撤销其他会话并清理其挑战/待绑定 |

现有 identity 全局数据库事务锁串行化登录、凭据重置、因子消费、会话撤销与安全变更；锁内重新确认调用会话仍有效，不能仅相信进入控制器时通过的 SessionGuard。安全状态变化后撤销旧挑战，防止使用旧密码通过的挑战取得新会话。

## 部署重置与备份恢复

部署侧重置密码默认保留已启用 TOTP，清理会话、挑战和待绑定。只有部署管理员明确选择应急重置 2FA，才同时清除已启用密钥和全部恢复码；不得把改 `.env` 密码或普通密码恢复当作默认绕过 2FA 的入口。工具及服务记录操作类型和结果，不输出密码、种子、验证码或恢复码。

备份包含认证持久状态；恢复仍要求原主密钥与匹配应用版本。恢复检查已启用 TOTP 密文可解密，在同一恢复事务中清理全部会话、挑战、待绑定及恢复码，保留已启用因子。清除恢复码避免旧快照复活已经消费的码，登录后需要重新生成并保存一组。最后使用时间步提升为旧值与恢复时当前步的较大者；恢复后需等待下一轮动态码，不能重放恢复前当前步。

源实例必须按现有恢复规程停止；本项不改变收费任务冻结或远程写入关闭规则。遗失验证器且没有恢复码的管理员使用明确的部署侧应急恢复，不引入邮件、短信或身份问题。

## 界面与验证

账户安全页面和嵌入式重新登录使用现有 shadcn/ui、主题、可访问错误和移动布局。密码、验证码与待绑定信息只保存在需要它们的组件内；取消、成功或离开时清理。绑定完成前清楚显示“尚未启用”；显示恢复码时明确需安全保存；成功反馈说明其他会话已退出。重复提交禁用，网络失败保留可修正状态，不伪装为成功。

测试分为密码/TOTP 标准向量与契约、真实 PostgreSQL 事务/并发/重启、浏览器账户安全与嵌入式会话恢复、部署重置和恢复工具。兼容目标是标准 TOTP 配置；真实 Google/Microsoft 手机 App 扫码、目标 NAS 和外部 HTTPS 访问结果另记，不能以 fixtures 替代。

## 依据

- [RFC 6238](https://www.rfc-editor.org/rfc/rfc6238)：时间步、共享密钥与一次使用。
- [Google Key URI Format](https://github.com/google/google-authenticator/wiki/Key-Uri-Format)：标准扫码配置。
- [Google Authenticator](https://support.google.com/accounts/answer/1066447)、[Microsoft 添加第三方账户](https://support.microsoft.com/en-us/authenticator/how-to-add-your-accounts-to-microsoft-authenticator)：验证码应用兼容方式。
- [OWASP 多因素认证](https://cheatsheetseries.owasp.org/cheatsheets/Multifactor_Authentication_Cheat_Sheet.html)、[身份验证](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)：重新验证、恢复及因子变更边界。
