# P4 普通文章微信草稿投递验证

日期：2026-11-20。环境：Windows、Node.js 22、PostgreSQL 16、Chromium。真实公众号凭证与目标 NAS 验收尚未执行。

## 实现范围

- 分离服务、控制器、模块装配和 Worker Executor；编辑器拆出工具栏、文档扩展、元信息、修订预览及投递组件。
- Publishing 通过实际草稿用例所需的平台接口调用微信，微信请求、错误、渲染、图片 URL 与限额集中在平台目录。
- `POST /api/v1/deliveries/check` 检查账号和明确的已保存修订，不获取 token、不上传图片、不创建草稿。
- `POST /api/v1/deliveries` 要求明确确认；同一账号、修订和动作返回原投递，已成功意图不会再次新增草稿，新修订可创建新意图。
- Worker 上传封面和正文图片，远程映射按账号、素材和用途分别保存；最终 HTML 全部使用微信图片地址，包含作者、摘要和原文链接。
- 固化最终 payload、HTML、修订、账号、凭证版本、排版版本和素材证据。缓存命中明确标记，实际远端副本字节未知时不伪造上传哈希或大小。
- 微信字段与图片官方页面已读取；检查原始字段和替换图片后的最终 HTML，明确记录 UTF-16 与十进制字节的保守应用口径，详见 [官方依据](WECHAT-API.md)。
- 全局单 Worker、账号锁和执行标识共同约束执行；每次平台请求前重新检查执行权。单次请求最多 30 秒，图片读取/压缩及平台请求受任务剩余时限约束。
- 已知失败需显式重试；危险提交中的未知结果仍需先停止 Worker 并人工核对，不自动重发；保留 P2 固定测试草稿入口。
- 前端显示账号、标题、修订号、保存时间和检查结果；有未保存内容时先提示保存，提交后查看原任务，网络未知时保持同一目标。

新增单元覆盖：32/16/120 字段边界、补充 Unicode、严格少于 20000 字符单位和 1000000 UTF-8 字节、原文 URL、可信图片 URL、上传副本、缺映射、请求前执行权检查和任务剩余时限。

新增集成覆盖：认证/CSRF/确认门槛、无副作用预检、并发重复提交、不可变排队快照、完整最终 payload、封面与正文及账号隔离、替换后 HTML 超限、坏映射失效与显式重试、未知结果不重发、人工确认来源、凭证竞争和旧执行者隔离、准备/危险阶段恢复差异。

浏览器已覆盖：保留 P2/P3 操作；普通文章确认与成功结果、已有意图返回、相同本地图片跨用途与账号、提交前未保存提醒、未知结果查看与不重发、真实 API 响应迟到时锁定原账号、390px 不完整文章阻止投递。迟到响应测试仅延迟真实 API 的网络返回，所有业务响应仍来自真实 API 和数据库。截图在被忽略的 `test-results/`，模拟微信审计检查不存在发表或群发调用。

早期一次浏览器运行触及原五分钟总时限，已执行的 P2/P3 用例没有业务断言失败；随着 P4 用例加入，总时限调整为十分钟后完整 12 项通过。测试脚本清理本次自有进程、隔离 schema 和临时素材；清理异常单独记录，不覆盖原测试错误。

最终单元复核有一项配置生成测试因本机子进程启动超时而失败，单独重跑通过；未放宽原有断言或该项超时。
