## 阶段门槛

1. SPEC：确认用户目标、范围、非目标和验收标准。
2. PLAN：确认技术设计、依赖顺序、验证方案与已知限制。
3. IMPLEMENT：按里程碑实施，变更需求先回写 SPEC/PLAN。
4. VERIFY：执行检查并报告已通过/失败/未执行，不以模拟测试替代真实平台验证。
5. RELEASE：整理运行文档、升级/恢复方式与发布包，不自动公开 GitHub 仓库或发布外网。

## 已知限制与处理

- 尚无用户公众号凭证：先验证模拟链路，真实验收保持待执行。
- 尚未确认 NAS CPU/内存：先支持可移植构建，不承诺所有架构已实测。
- 第三方接口并不保证新增草稿幂等：不确定状态需人工核对，避免盲重试。
- 微信官方文档本轮抓取失败：实际权限、字段及图像限额、token 方案在 P2 核验，不沿用脚手架常数或推测。
- 单 Worker 是首版部署约束；确有吞吐需求时再评估队列系统和并发，而非先行扩容设计。
- 没有远程素材清理与本地垃圾回收：可能积累未引用文件或远程素材，交付说明写明人工维护方式。
- 原有代码在需求定稿前产生：只视作候选脚手架，测试和验收从零记录。
