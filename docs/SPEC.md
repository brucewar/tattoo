# Tattoo 产品目标与分阶段需求规格

- 状态：Accepted / 已确认（2026-11-24）
- 版本：0.8
- 日期：2026-11-24（Asia/Shanghai）
- 项目：Tattoo
- 代码仓库：[brucewar/tattoo](https://github.com/brucewar/tattoo)
- 关联文档：[技术设计](ARCHITECTURE.md)、[实施计划](PLAN.md)
- 2026-11-23：用户确认继续需求对齐后的实现，本轮执行第 10 节模型配置、AI 写作/改写及封面/插图；P0–P5 的历史阶段记录不代表完整产品已完成。

## 1. 目标与完成定义

Tattoo 的完整产品目标是为个人内容创作者提供自托管工作台：通过 RSS、搜索和指定链接获取资料，使用 AI 写作、改写和配图，经人工编辑后形成微信公众号草稿、知乎内容导出，以及小红书文案与图片导出；后续平台接口接入按可行性逐步推进。

用户于 2026-11-20 再次明确：保留上述完整目标，先完成现有文章到微信公众号草稿箱的闭环，再开展资料获取与 AI。当前继续使用 PostgreSQL 持久任务表，出现明确需求后再评估 Redis/BullMQ，详见 [队列架构决策](adr/0001-postgresql-task-queue.md)。整体目标、第一阶段范围和已实现能力分别记录。

第一阶段在标准 Docker Compose 环境中完成：管理员登录 → 配置微信公众号 → 验证接口 → 创建并编辑文章 → 上传图片 → 预览 → 后台自动存入公众号草稿箱 → 查看投递记录。

第一阶段的“自动存草稿”指用户提交后由后台完成排版、图片上传和创建远程草稿；不包含自动选题、AI 写作和周期性批量生成。当前目标账号是个人主体、未认证公众号。

只有真实账号的测试草稿在微信后台可见，才可以宣布真实投递链路通过。模拟服务验证只能证明实现与测试场景一致，不代表微信真实权限已验证。

## 2. 用户与使用环境

- 第一阶段为单管理员实例；需要登录，无开放注册。
- 部署支持运行 Linux 容器的 Docker Engine 与 Docker Compose，不绑定 NAS 品牌、型号或内存配置。镜像架构与 Docker 平台匹配，验证记录区分已实测和未实测平台。
- 首先通过局域网浏览器访问；桌面完整可用，手机支持查看、基础编辑、账号配置及投递操作。
- 家宽出口可能变化。微信 API 白名单使用实际出站公网 IP，与 Docker 主机内网地址和 DDNS 不同。
- 平台密钥由用户在自己的部署环境输入，不要求在聊天中提交。

## 3. 用户流程与功能需求

### FR-01 管理员与会话

使用环境配置初始化首个管理员；重复启动不覆盖已有密码。用户可登录、退出，会话可过期。未登录不能读取文章、素材、账号、投递记录或执行操作。登录限流，错误提示不泄露账号是否存在。

验收：正确密码能登录；错误密码被拒绝；退出后原会话立即失效；重启后已有管理员不被重建；跨站写请求被拒绝。

补充：提供部署侧管理员密码重置命令，重置后撤销全部旧会话；不增加邮件找回流程。初始密码不得保留在镜像或日志中，初始化完成后可从部署配置移除。

### FR-02 公众号账号配置

保存账号名称、AppID、AppSecret。后端加密保存 AppSecret，响应和日志不返回明文。允许修改名称、轮换密钥；第一阶段 AppID 创建后不可修改，避免历史投递和素材归属混乱。不支持删除已有投递记录的账号。

支持配置多个公众号，AppID 在实例内唯一；每次投递只选择一个账号。第一阶段不提供账号删除入口。更新账号凭证与远程写操作互斥：有任务执行时拒绝轮换，并提示等待；排队任务执行时读取最新凭证。凭证版本用于阻止旧验证结果覆盖新状态。

显示账号当前能力、验证来源和验证时间；“曾验证通过”不保证永久可用。读取草稿与新增草稿分别验证，不能用获取 token 或读取数量成功推断新增草稿成功。网络故障不直接判为无权限。当前个人账号不展示自动发表或群发入口。

验收：刷新可读取账号信息但读不到密钥；修改密钥会使旧 token 缓存失效，并将相关能力恢复为未验证；未授权接口显示具体错误与修复指引。

### FR-03 接口验证

提供只读验证入口：获取 token → 读取草稿数量。提供显式的创建测试草稿操作，需要封面，且告知会创建远程素材与草稿。报错展示脱敏后的错误码、说明与建议；`40164` 显示微信报告的出口 IP。

测试草稿使用固定且明确标识的测试正文，与正常投递共用持久任务、去重和不确定结果处理；每次新的测试须显式发起，重复请求返回同一任务。测试产物保留 ID，由用户在微信后台按需清理，系统不自动删除。只读验证失败不阻断本地写作。

验收：只读验证不上传图片、不创建草稿；完整验证只有收到创建草稿成功结果后才标记新增草稿可用；进入新增草稿提交阶段后的请求超时进入待核对状态。

### FR-04 文章编辑与修订

可新建、列出、打开、编辑文章。字段包含标题、作者、摘要、来源链接、正文、封面。正文支持段落、二/三级标题、加粗、斜体、删除线、下划线、列表、引用、代码块、分隔线和本地上传的图片。

正文以结构化文档保存，图片引用素材 ID。新稿默认“未命名文章”，允许保存缺少封面、空正文或尚不满足微信限制的草稿；结构和安全校验始终执行，平台完整性校验在投递前执行。每次内容有变化的显式保存形成不可变修订；无变化保存返回当前修订。保存时使用版本号检查冲突。初版采用明确保存按钮和未保存提示，不承诺自动保存。可查看已保存修订，历史内容不会被后续编辑覆盖。

第一阶段只有一份稿件及一套修订，微信公众号是其投递目标；不同时维护基础修订和平台修订两套快照。独立平台版本在第二个平台实际接入时引入。知乎、小红书只显示扩展说明，不出现可点击但无实现的发布按钮。首版不增加文章删除、修订回滚和对比界面。

验收：保存后刷新内容一致；两处编辑产生冲突时明确提示，不静默覆盖；离开未保存内容时提醒；历史修订与当前内容可区分。

投递前展示账号、修订号、保存时间及标题；有未保存内容时提示先保存，不能把旧修订悄悄当作当前编辑内容投递。已排队内容不受后续编辑影响。

### FR-05 素材管理

支持上传 JPG/PNG，限制请求大小与解码像素。服务端检查真实图像格式并规范化重编码，文件名不得决定磁盘路径。第一阶段不从任意远程 URL 下载图片。相同内容可去重。历史修订引用的素材必须保留。

首版采用编辑器内上传和封面选择，不另建独立素材库管理页。粘贴外部富文本只接受支持的结构；外链图片明确提示需本地上传，不能静默下载或丢失。图片处理应用方向信息并去除非必要元数据。原始素材与面向微信压缩后的上传副本分开，不能为满足平台大小限制覆盖本地原图；无法压缩达标时给出可操作错误。

验收：合法图像可用于封面与正文；伪装图像、SVG、超限文件被拒绝；素材读取要求登录；文件写入失败不会留下可引用的损坏素材记录。

### FR-06 平台预览与投递前检查

提供一套固定公众号排版与标题、摘要、作者、封面、正文完整性检查；首版不做模板市场、主题编辑器或代码语法高亮。不支持的正文节点明确报错，不静默丢弃。排版处理 HTML 转义；来源链接只允许 http/https，正文中的安全外链显示为“文本 + URL”，危险链接拒绝保存。网页预览只作为近似效果，最终以微信后台为准。

验收：脚本、事件属性、危险 URL 无法执行；正文图片通过素材 ID 解析；缺封面、空正文、超出平台限制时无法提交。具体限制引用官方文档并在平台模块集中维护。

投递前检查原始字段、压缩后图片及替换微信图片 URL 后的最终 HTML；限制表必须写明计量方式（字符/UTF-8 字节）、官方来源、核验日期和边界测试，不直接沿用脚手架中的常数。不截断标题、摘要或正文来伪装校验通过。官方条目未核验时标注待核验，不宣称平台兼容性已通过。

### FR-07 后台存入微信草稿箱

选择账号与已保存修订后提交后台任务，每次仅创建一篇单图文草稿，不做多图文合集。任务绑定不可变修订和渲染版本。Worker 获取凭证、上传封面和正文图片、替换图片地址、创建草稿，并保存远程 `media_id` 与执行记录。

第一阶段只新增远程草稿，不自动修改或删除微信侧已有草稿。新增草稿能力未验证时，可以通过明确的首次测试投递验证，不能仅因“未验证”永久阻止接入。

投递记录表示当次执行结果，不持续同步用户在微信后台后续进行的编辑、删除或发表。

验收：用户提交后可离开页面，后台继续执行；正文图片使用微信上传接口返回的地址；封面使用永久素材 ID；系统不调用发表或群发接口。

### FR-08 投递状态、去重与恢复

状态为：排队中、执行中、已存草稿、失败、结果待核对。每次执行保存阶段、时间、错误、远程 ID。重复提交同一账号、同一修订、同一动作返回已有投递，不创建第二篇草稿。确定失败的任务可显式重试。

成功投递不提供再次创建入口；修改内容并保存新修订后可新建草稿，并提示旧草稿仍保留。重新测试、失败重试、人工核对均记录操作者、原因和时间。排队任务首版不提供取消功能。

进入新增草稿提交阶段后发生超时、连接断开、无法解析响应或 Worker 重启，可能已经在微信创建草稿，必须进入待核对状态，不自动重复提交；HTTP 5xx 本身不能证明未创建。尚未进入提交阶段的中断可以恢复。允许用户在微信后台检查后记录“确认已创建”及远程 ID，或“确认未创建”后显式重试；操作留记录。确认已创建必须填写核对说明，远程 ID 可在微信后台无法取得时留空，但界面须标明“人工确认”，不得伪装为接口已验证。人工核对不自动将账号新增草稿能力改为接口验证通过。

只有旧 Worker 已停止或确认释放执行权，才允许人工解除不确定状态并重试；不能只等租约超时就让新旧执行者同时写入。素材上传也可能留下远程孤立素材，记录该限制，不承诺全链路恰好一次；首版不做微信素材自动清理。

验收：双击提交与任务重复扫描不会重复投递；排队状态在重启后可恢复；危险阶段故障不盲重试；一个账号的上传序列不会因并发任务交叉破坏素材映射。

### FR-09 扩展能力

稿件修订、平台账号、投递时的渲染产物、素材映射与投递记录分开建模。微信公众号字段只在平台模块与平台结果中处理。首版只实现读取草稿和新增草稿的逐账号验证状态；发表、群发、导出不实现，也不显示可用入口。不预建多个平台的版本树、通用插件协议或无实现的适配器。

验收：内容编辑、修订存储、任务调度不依赖微信 `media_id` 等平台专有字段；投递结果包含平台标识和独立结果数据；新增平台无需重写稿件存储。未来平台可能有不同动作与状态，首版不承诺通用状态机覆盖所有平台。

### FR-10 部署与运维

提供 Docker Compose，包含 api、worker、postgres，使用数据库持久任务表；当前不引入 Redis、BullMQ 和独立 Outbox。前端页面与后端合并为一个应用镜像，API 与 Worker 共用该镜像，仅 API 映射宿主端口并提供前端页面。提供配置生成、健康检查、持久化、数据库迁移、备份恢复与升级说明。固定单 Worker、全局并发 1，不提供提高并发的配置。此处为 2026-11-24 用户确认后的部署结构，历史四服务验证记录保留其原始范围。

引入资料获取或 AI 本身不触发队列迁移。出现明确的吞吐、多 Worker、任务隔离、优先级或延迟执行需求，且现有方案经验证不适合时，再评估 Redis/BullMQ，并另行设计迁移和一致性；不预设迁移日期。

验收：新目录按文档可启动；缺少必要密钥时拒绝启动；重复部署不丢文章和管理员；重建容器后图片与数据仍可用；数据库迁移失败不继续启动应用；备份可恢复到空实例。

首版允许停机备份：暂停写入、停止 Worker 并确认无活动调用后，一起备份数据库和素材；主密钥单独备份。恢复环境默认禁止远程写入，恢复来的排队/执行中任务先核对再显式启用 Worker，防止重复创建。数据库迁移后的回滚以恢复匹配版本备份为准，不承诺只回退镜像即可安全降级。记录 Docker/Compose 版本、镜像架构和实际运行结果，不将指定 NAS 型号或硬件实机验收作为交付门槛。备份工具可在管理电脑操作目标 Docker 引擎，目标主机不额外依赖 Node.js。

## 4. 非功能要求

- NFR-01 安全：HttpOnly 会话、CSRF 防护、密码派生哈希、登录限流、密钥认证加密、日志脱敏；不开放任意文件读取和远程 URL 代理。
- NFR-02 一致性：数据库为任务与内容事实来源；Delivery 本身就是持久任务，事务提交后才能被 Worker 认领；认领和状态更新使用条件约束；重复扫描、进程重启和重复请求不得盲目重放危险动作。
- NFR-03 性能：网页请求仅创建任务，不同步等待外部上传；列表分页；图片解码、上传、请求时间有明确上限。
- NFR-04 可用性：表单有标签、键盘可达、焦点可见；状态不仅用颜色表达；有加载、空状态、失败和冲突处理；窄屏不出现无法操作的横向布局。
- NFR-05 视觉：简洁的中文内容工作台，采用一致排版、间距和状态体系；不使用虚假统计或模拟文章伪装真实账号数据。
- NFR-06 工程：严格 TypeScript、锁文件、模块化结构、CI、MIT 许可证、贡献与安全说明；关键状态机、接口适配、安全与恢复路径有测试。

第一阶段的应用上限（不是微信平台限额）：单文件上传 10 MiB、解码 2000 万像素、单份正文 JSON 2 MiB、节点 5000、嵌套深度 30；列表默认 20、最多 100 条；单次外部请求 30 秒、整次任务 10 分钟。超限给出具体错误；进入新增草稿提交阶段后的超时按结果待核对处理。代理、API、Worker 使用一致配置。微信平台上限另按 FR-06 核验并执行。

P6–P8 的模型生成在后台执行，模型 HTTP 请求上限为 5 分钟，生成图片的地址下载另限 30 秒；网页提交与查询不等待模型完成。模型请求中断不自动重发，避免隐式重复计费。

## 5. P0–P5 基础阶段的范围边界

自动选题、联网采集、AI 写作、AI 配图、每日周期生成；知乎和小红书真实投递；浏览器模拟登录；微信公众号发表和群发；多人协作、公开注册、复杂角色；视频；付费订阅；插件市场；数据分析大屏。

资料获取、AI 写作/改写/配图、知乎与小红书导出仍属于已确认的完整产品目标，安排在微信草稿闭环之后，具体规格与验收在对应阶段细化。自动选题和周期生成的需求仍待后续确认；本轮没有增加这些交付承诺。

这里的“不包含”仅描述 P0–P5 的阶段范围，不从完整产品需求中删除这些能力。当前阶段实现不能作为整个 Tattoo 产品已完成的依据。2026-11-23 的补齐提案见第 10 节。

这些功能不以假按钮或空实现进入第一版。第一阶段的安全边界仍有效，后续资料获取需另行定义网络访问规则。

## 11. P9 资料获取（2026-11-24）

用户确认继续按计划实施，并选择 Tavily API 作为搜索服务。本阶段增加“资料”入口：指定链接提取、RSS/Atom 订阅与手动拉取、Tavily 按需搜索及明确选择结果后采集，保存的资料可选入 AI 写文章。复用 TypeScript、PostgreSQL 持久任务和现有单 Worker。

- 链接读取公开 HTTP/HTTPS 页面的正文和标题，保留输入 URL、最终 URL、发布时间（可获取时）、获取时间及内容摘要值。规范化 URL 判重，重复获取使用同一资料 ID；不依据任意页面声明的 canonical 自动合并不同地址。
- RSS/Atom 每次最多处理 20 个条目，文字按订阅提供的内容保存，并标明可能仅为摘要；用户可明确提取条目全文。刷新订阅不自动遍历抓取所有链接，也不覆盖已取得的网页全文。取消订阅保留已保存资料及来源信息。首批不增加定时采集、自动评分、热点榜或日报。

- 每次 URL 访问及重定向都检查公开地址、DNS 和连接地址绑定，拒绝私网、环回、保留及元数据地址；生产仅使用 HTTP 80 / HTTPS 443。跳转最多 3 次，下载总时限 20 秒，压缩前后均最多 2 MiB。解析不执行脚本、不加载子资源、不抓图片；不支持的页面、登录墙或无法识别的正文明确失败。只允许测试环境中模拟服务的精确环回来源例外。
