# 常见问题

[文档首页](README.md) · [部署指南](DEPLOYMENT.md) · [开始使用](GETTING-STARTED.md) · [运行维护](OPERATIONS.md)

## 我的 NAS 能运行吗？支持 ARM 吗？

当前发布并验证的是 `linux/amd64` 镜像，适用于提供 Linux 容器及 Docker Compose v2 的 x86-64 主机。当前没有 ARM 镜像，也没有公布经过验证的最低内存指标。请按架构和容器能力判断，不按 NAS 品牌判断；其他架构不要强行当作已经支持。具体环境见[部署前确认](DEPLOYMENT.md#部署前确认)。

## 已经合成一个镜像，为什么还有三个容器？

一个 Tattoo 应用镜像包含前端、API 和后台 Worker。Compose 用它运行 `api` 与 `worker` 两个进程容器，数据库使用官方 PostgreSQL 镜像，因此一共三个容器。只有 API 暴露 Web 端口；数据库和素材分别持久化，更新应用不用重新创建数据。

## 必须先提供模型 Key 或微信 AppID 吗？

不需要。部署并登录后可以先手写文章、上传图片、保存修订和预览。使用 AI 时再配置模型，搜索时再配置 Tavily，存入微信草稿时再配置公众号。密钥只输入自己的实例，不提供给开发者。操作顺序见[开始使用](GETTING-STARTED.md)。

## 页面打不开或登录失败，怎么排查？

先在部署目录执行 `docker compose ps`，再看[服务日志](OPERATIONS.md#查看状态与日志)。确认访问的是 Docker 主机的地址、Web 端口没有占用且允许局域网访问；在另一台电脑浏览时，`localhost` 指那台电脑自己。

登录或写入失败时，核对 `.env` 的 `APP_ORIGIN` 是否与浏览器实际协议、主机和端口完全一致。改动后重新创建 API 和 Worker，见[局域网与 HTTPS](OPERATIONS.md#局域网与-https)。初始管理员来自第一次启动的配置，之后改 `ADMIN_PASSWORD` 不会覆盖已有密码；忘记密码使用[管理员密码恢复](OPERATIONS.md#管理员密码恢复)。

## 可以修改密码、使用谷歌或微软验证器吗？

`0.1.0-rc.2` 候选版本的 P14 账户安全提供网页改密、可选 TOTP 双重验证、一次性恢复码和退出其他会话，保留单管理员。Google Authenticator 与 Microsoft Authenticator 均按通用二维码配置；每组动态码成功使用后不能重用，连续操作时等待下一组。版本、发布状态与实际验收见[版本说明](RELEASE-NOTES.md)和[P14 验证记录](P14-VERIFICATION.md)。

恢复码只在启用或重新生成时显示，重新生成使旧码全部失效。手机不可用时可用未使用恢复码；两者都丢失则需要明确的部署应急重置。普通密码重置仍保留已启用验证器。群晖 Container Manager 无 SSH 操作步骤见[账户安全](ACCOUNT-SECURITY.md)。

## 文本能生成，图片却报错；或者模型接口返回 404？

文本与图片分别配置和验证。文本支持 Chat Completions、Responses、Anthropic Messages；图片独立使用 Images Generations，不使用 Responses 的图片工具或 Anthropic 图片接口。

检查协议、Base URL 的版本路径、模型 ID、额度、图片尺寸与返回格式。不要把完整的 `/chat/completions` 等端点再填入 Base URL。Docker 内的 `localhost` 指应用容器自身；模型地址需由容器可达，且服务地址要求 HTTPS，仅回环地址允许 HTTP。完整参数见[模型配置](MODELS.md#配置模型)。

## 主题文章生成成功，封面失败，需要全部重做吗？

不需要。主题任务保留文章候选，使用“仅重新生成封面”只发起新的图片请求。切页或刷新后从主题创作记录找回原任务。若文章和封面都已成功、仅最终保存中断，使用“完成保存”保存已有结果，不再次调用模型。

后台没有自动重试收费请求；请先看清任务状态和服务商记录，再明确重新生成。编辑器内的单项 AI 结果仍需手动采用并保存，和主题创作自动保存新稿的入口不同。

## 关闭远程写入后，为什么模型或搜索仍可能计费？

`REMOTE_WRITES_ENABLED` 只控制微信素材及草稿写入。实际生成验证、AI 创作和明确发起的 Tavily 搜索会调用自己的服务商，可能计费；保存配置本身不等于执行验证。收费请求遇到中断或不确定结果时不会自动重新发送，明确重新生成或搜索才会发起新请求。说明见[模型任务](MODELS.md#任务与失败处理)和[Tavily 搜索](SOURCES.md#tavily-搜索)。

## 微信只读验证通过，为什么还不能存草稿？

取得 token、读取草稿和新增草稿是不同的权限。确认账号实际具备官方草稿接口权限、部署已明确启用远程写入、封面和正文通过本地检查。`40164` 应按微信错误中报告的实际出站公网 IP 配置白名单，NAS 内网 IP 或 DDNS 地址不能直接代替它。

当前只创建微信公众号官方草稿，不直接发表、群发，也不自动发布到知乎或小红书。资料和 AI 生成不会自动触发微信投递。配置及检查见[微信接入](OPERATIONS.md#微信接入与家宽出口)。

## 任务显示“结果待核对”，可以直接再点一次吗？

先核对原任务。“结果待核对”（`UNCERTAIN`）表示调用结果无法确认，远端可能已经成功；重新发送可能新增草稿或再次产生模型费用。创建任务的响应丢失时，先获取同一请求的记录。

微信任务需要先停止对应 Worker，到微信后台检查，再填写人工结论；明确未创建后才显式重试。模型和搜索任务先检查服务商记录及已有结果。恢复备份也会冻结旧排队/执行任务，不自动重放。具体操作见[处理待核对任务](OPERATIONS.md#处理结果待核对的任务)。

## 更新或搬家时，要保存哪些文件？

保留同一次停机一致备份中的数据库与素材，另行保管原 `.env`、加密主密钥、匹配的 Compose 及应用镜像。只复制素材目录或只留镜像都不能完整恢复；备份不包含主密钥、完整配置和镜像。不要用 `down -v` 或卷清理代替普通更新。

当前备份恢复工具需要管理电脑具备 Node.js 22、Docker CLI 和匹配版本源码，Docker 运行主机本身无需安装 Node.js。获取工具、固定版本升级、空实例恢复和迁移流程见[运行维护](OPERATIONS.md)。不要依赖当前尚不存在的 `latest` 标签自动升级。
