# P3 内容编辑与修订验证

日期：2026-11-20。环境：Windows、Node.js 22、PostgreSQL 16、Chromium。

## 实现范围

- 文章列表、新建、打开和显式保存；空标题使用“未命名文章”，允许空正文、缺封面和尚未满足平台限制的稿件保存。
- Article + Revision 单套快照。事务写入文章、修订和素材引用；内容未变复用原修订，过期版本返回 `409 VERSION_CONFLICT`。
- 历史只读查看、指定已保存修订的公众号近似预览；当前未保存内容不能混入旧修订预览。
- Tiptap 二/三级标题、文字样式、列表、引用、代码、分隔线、换行、本地图片和安全正文链接。存储图片只含素材 ID，正文链接渲染为文字与 URL。
- 图片安全解码、重编码、方向处理、元数据移除、哈希去重和受保护读取；微信压缩副本不覆盖本地素材。
- 外部富文本只接受支持的结构，外链图片和危险内容明确拒绝；多文件粘贴/拖入提示逐张处理，不静默遗漏。
- 保存冲突保留本地编辑；导航、退出和浏览器离开有未保存提醒。会话过期后通过重新登录恢复仍在内存中的编辑。
- 一套固定排版 `wechat-editorial-v2`，没有新增主题、独立素材管理页、修订回滚或第二套修订树。

Windows 配置生成测试包含两次真实 Node 启动，增加单进程超时与总测试时限，保留随机密钥、日志不泄露和拒绝覆盖断言。浏览器保存等待对应本次修订的客户端成功提示及按钮可用，避免将上一次保存状态误认作本次完成。

浏览器前端使用开发运行模式，API/Worker 保持测试模式与隔离模拟微信。组件库在 `NODE_ENV=test` 会固定对话框标题 ID，不能把这类单元测试替身带入真实浏览器验收。历史列表与预览切换显示；测试等待关闭动画结束再操作恢复的历史列表。编辑器切换可编辑状态不触发内容更新，保存反馈不会因此被清除。

运行入口：

```bash
npm run format:check
npm run typecheck
npm test
npm run build
docker compose -f compose.test.yaml up -d --wait
```

设置独立的 `TEST_DATABASE_URL` 后执行 `npm run test:integration` 和 `node tests/e2e/run-p2.mjs`。后者沿用 P2 的真实 API、Worker、Vite 和模拟微信隔离环境，运行 P2/P3 全部浏览器用例，不拦截浏览器 API 伪装业务成功。

重点断言：

- 保存/刷新一致、无变化不增版本、历史正文和图片引用不可变、并发保存只有一个成功。
- 不存在的素材或非法文档不留下部分文章/修订；历史修订必须属于当前文章；P2 固定测试稿不混入正常内容列表。
- 未登录拒绝读取稿件和素材；CSRF 仍生效；未知结构、危险链接、原型属性、非法 Unicode 和超过应用上限的文档被拒绝。
- 浏览器实际输入、排版、上传图片、保存、刷新、查看历史和预览；冲突不丢稿，过期后重新登录可继续保存。
- 外链图片粘贴不发起远程下载；预览脚本被转义，安全链接以文字和 URL 展示，图片通过受保护接口实际加载。
- 390px 窄屏编辑与预览无页面横向溢出，工具按钮可键盘聚焦。截图保存在被忽略的 `test-results/`，不替代功能断言。

## 阶段边界

普通文章投递、投递前账号/修订确认以及完整平台限额校验属于 P4；P2 的固定测试草稿入口继续可用。预览明确提示微信现行限额待核验，不代表已通过平台投递检查。真实微信公众号和目标 NAS 架构验收仍未执行，沿用 [P2 验证记录](P2-VERIFICATION.md) 的未完成项。

本轮没有数据库结构变更；历史快照沿用已存在的 Revision/RevisionAsset 约束。会话恢复只保留当前页面的内存编辑，不能恢复关闭页面或崩溃后尚未保存的内容。
