## 自动检查的运行方式

源码检查与生产构建：

```bash
npm ci
npm run format:check
npm run typecheck
npm test
npm run build
```

独立 PostgreSQL 与浏览器检查：

```bash
docker compose -f compose.test.yaml up -d --wait
npm run test:integration
node tests/e2e/run-p2.mjs
docker compose -f compose.test.yaml down
```

执行前显式设置专用 `TEST_DATABASE_URL`，数据库名称必须含 `test`；示例与 Shell 设置方法见 [开发说明](DEVELOPMENT.md#独立数据库集成测试)。先安装锁文件对应 Chromium，或在本机用 `TATTOO_E2E_BROWSER_EXECUTABLE` 指定现有浏览器；不要把本机绝对路径写入仓库。浏览器脚本使用隔离 schema、真实 API/Worker 与模拟微信，名字沿用 P2，实际运行该目录中的 P2 至 P5 用例。

Docker 验证在镜像构建后执行：

```bash
docker compose build
node scripts/verify-foundation.mjs
npm run verify:recovery
```

`verify-foundation` 使用保留给测试的 `tattoo-p1-smoke` 项目与端口，不能指向真实部署；它验证启动和重建，不代替恢复演练。`verify:recovery` 在随机隔离项目实际执行备份恢复，要求发布端口可从管理电脑的环回地址访问；不自动配置远程 Docker 网络。日常演练也可按 [运维说明](OPERATIONS.md#恢复到空实例) 在单独空项目执行备份恢复，并记录原实例/目标实例、数据比对及任务隔离结果。错误路径只在隔离实例和备份副本上验证。

测试报告至少区分通过、失败与未执行，并记录源码版本、命令、环境和结果。CI 通过还需引用对应提交的运行链接；Docker 恢复与真实微信分别保留证据，不以构建输出替代运行结果。

## AT-09 真实微信验收

以下操作由用户在自己的环境完成，AppSecret 仅输入本机页面；不要把 AppSecret、主密钥、管理员密码或完整配置交给聊天或公开记录。按顺序执行，只有实际完成的步骤才能写“通过”。

1. 记录测试日期、部署提交和镜像 ID、浏览器访问来源、账号的本地标识及实际出站 IP。确认 IP 白名单已生效，先保持 `REMOTE_WRITES_ENABLED=false`。
2. 登录后在公众号账号设置中填写真实 AppID/AppSecret，刷新后确认页面不显示密钥。运行只读验证；分别记录 token 和草稿读取结果，确认此时没有新增测试稿。
3. 通过本机配置显式启用远程写入并重新创建 API/Worker/Web。上传一张可识别的测试封面，明确确认创建固定测试草稿。记录本地投递 ID、接口结果来源和远程草稿 ID；到微信后台查看该测试草稿及封面。
4. 新建普通文章，使用可识别标题、作者、摘要、原文链接，加入常用段落/标题/列表和至少一张正文图片，并选择封面。保存后记录修订号和时间；打开同一已保存修订的微信预览。
5. 点击“存入微信草稿”，核对目标公众号、文章标题、修订号和保存时间，再明确确认。查看后台任务结果，记录投递 ID、修订号、成功时间和远程草稿 ID。
6. 在微信后台打开普通草稿，检查标题、作者、摘要、封面、正文图片、主要文字、链接表现及基本排版。预览不要求与微信逐像素一致，但图片不得缺失，正文不得被静默截断；页面显示的稿件与已确认修订应一致。
7. 再次查看或提交同一账号、修订的本地意图，确认返回原投递，不新增第二篇草稿。首版不自动同步后台后续编辑或删除；测试中不要据此推断草稿始终与本地一致。
8. 记录测试产生的草稿、测试封面及正文素材，保留便于人工识别的信息和可取得的远程 ID。是否保留或删除由用户在微信后台决定，系统不自动清理远程产物；实际清理情况也写入记录。

只读验证成功不能替代新增草稿成功。接口明确无权限时记录失败及脱敏错误，先决定更换账号或调整目标；不以重复盲试冒充验收。新增草稿提交后连接中断或超时，可能已经创建成功，应执行 [停止 Worker 与人工核对](DEVELOPMENT.md#显式创建测试草稿)；人工确认的结果不记作“微信接口已返回成功”，也不自动证明新增权限已通过。

完成测试后，按自己下一步使用计划决定保留写入开关还是恢复 `false`，使配置在重建后生效。不得为了验收故意重复制造不确定的真实远程提交；危险阶段与恢复防重放由隔离模拟测试覆盖。

## 执行记录模板

记录保存在自己的受保护位置。公开项目记录只引用脱敏结论，不提交真实稿件、密钥或完整环境配置。

| 字段          | 应记录的内容                                                                                            |
| ------------- | ------------------------------------------------------------------------------------------------------- |
| 日期 / 执行者 | 实际执行日期和操作者。                                                                                  |
| 版本 / 平台   | 源码提交、应用/Web 镜像 ID、PostgreSQL 主版本、Docker/Compose 版本及实际平台。                          |
| 场景          | AT 编号、原实例与恢复实例的标识、是否模拟微信或真实微信。                                               |
| 操作 / 命令   | 本次执行步骤和返回结果，省略凭证；没有执行的明确注明。                                                  |
| 数据证据      | 文章与修订 ID/版本、素材哈希或比对结果、账号解密成功结论，不能记明文密钥。                              |
| 恢复证据      | 归档校验结果、空目标检查、密钥/镜像匹配、原会话撤销、各任务状态及事件、远程写入禁用和 Worker 停止状态。 |
| 微信证据      | 账号脱敏标识、测试稿与普通稿投递 ID/远程 ID、结果来源、后台实际检查结论、遗留产物管理情况。             |
| 结果 / 限制   | 通过、失败或未执行；错误与修复结论；截图或日志的受保护存放位置。                                        |

没有真实凭证与现场检查条件时，最终交付说明保留“真实微信验收未执行”。其他 Docker 平台未实测的限制单独写明，不再以特定 NAS 型号作为阻塞条件。
