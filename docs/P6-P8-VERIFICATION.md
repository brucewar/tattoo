## 覆盖的关键行为

- 文本和图片独立配置与验证；密钥加密、读取脱敏、空值保留、显式清除。跨来源换服务不默带旧密钥；配置版本变化使旧排队任务停止。
- 唯一请求标识防重复调用。创建响应丢失后刷新或切页，使用原标识找回已提交任务；浏览器无法持久保存标识时不提交模型请求。
- 模型调用、图片下载、响应大小有边界；拒绝危险下载来源、重定向及无效图片。图片引用进入原素材流程，下载不携带模型密钥。
- 后台生成独立于 Delivery，单 Worker 顺序执行，微信写入关闭时仍可 AI 创作。网络中断/进程重启不自动收费重试；执行权条件更新阻止迟到结果写回。
- 文章、封面和插图先作为候选。采用时保护已有文字、正文图片、未保存修改和选区；保存才产生修订。明确被截断或过滤的模型文字不能被当作成功结果。
- 文章参考实际发送给图片模型，最多取 6000 字符摘录；验证图片使用固定提示，不隐式追加文本模型调用。
- 同一篇生成文章与封面、插图经过保存和预览，再由用户明确选择账号、勾选确认后完成模拟微信草稿。采用之前的生成过程没有微信调用。

## 执行入口

```bash
npm run build
npm test
npm run test:integration
node tests/e2e/run-p2.mjs

docker compose build
node scripts/verify-foundation.mjs
npm run verify:recovery
```

集成与浏览器检查需显式专用 `TEST_DATABASE_URL`，参考 [开发说明](DEVELOPMENT.md)。浏览器使用与锁文件匹配的 Chromium 159；需要时可用 `TATTOO_E2E_BROWSER_EXECUTABLE` 指定本机已有浏览器，不把开发机路径写入仓库。

Docker 备份恢复演练已扩展：实际 HTTP 保存加密模型配置；停止源 Worker 后准备五种生成状态，避免调用任何真实模型；恢复检查模型密钥解密、旧排队/运行任务冻结、既有终态和结果保留，且恢复应用不自动启动。恢复后 API 的配置响应不泄露密钥。

## 发现与修正

交叉检查补齐了图片请求携带正文参考、拒绝截断文字、跨来源密钥保护、请求响应丢失后的会话持久化，以及仅含图片的新稿采用确认。

首轮浏览器 17 项通过、2 项失败：预览图片断言误计关闭图标；第二次改写应点击“重新生成”，测试仍寻找“开始生成”。根据失败页面修正定位后，完整 19 项通过。随后同一生成稿显式投递微信的补强流程通过定点 8 项，未延长业务超时。

真实模型和微信权限需用户在自己的配置页面输入凭证后分别验收；不要在聊天、源码或公开日志中提供 API Key/AppSecret。操作见 [模型说明](MODELS.md) 与 [真实微信验收](ACCEPTANCE.md#at-09-真实微信验收)。
