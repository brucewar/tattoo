# 保留 PostgreSQL 持久任务表，按需求评估独立队列

2026-11-20，用户确认保留资料获取、AI 创作/配图和多平台产出的完整产品目标，先完成普通文章到微信草稿的闭环；队列继续采用现有 PostgreSQL 持久任务表与单 Worker，原始架构图中的 Redis/BullMQ 不在当前部署中引入。该选择减少 NAS 上的独立服务和维护成本，沿用已验证的事务提交与任务认领机制；资料获取或 AI 接入本身不触发迁移。

当明确的吞吐、多 Worker、任务隔离、优先级或延迟执行需求出现，且现有方案经验证不适合时，再评估 Redis/BullMQ，不预设迁移日期。若决定迁移，需另行设计数据库与队列的一致性，并保留投递唯一性、执行记录和不确定结果处理；未来各类任务的领域模型在对应阶段设计，现有 Delivery 仍表示平台投递意图。
